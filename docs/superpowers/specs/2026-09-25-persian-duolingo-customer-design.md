# طراحی تجربه‌ی مشتری فارسی و RTL برای پرودچی

## هدف

بازطراحی کامل تجربه‌ی مشتری با الهام از الگوی مسیر یادگیری Duolingo، بدون کپی کردن برند یا شخصیت‌های آن. رابط کاربری فقط فارسی و RTL است و روی موبایل و تبلت اولویت دارد.

## اصول تجربه

1. هر صفحه یک اقدام اصلی و واضح دارد.
2. مسیر مرحله‌ای مرکز تجربه است؛ کاربر همیشه می‌داند کجاست و قدم بعدی چیست.
3. گیمیفیکیشن باید وضعیت را سریع منتقل کند: XP، زنجیره، سطح، ستاره و باز شدن مرحله.
4. رنگ و حرکت نقش راهنما دارند، نه تزئین دائمی.
5. هیچ متن انگلیسی در UI نمایش داده نمی‌شود؛ کلیدها و نام‌های داخلی API می‌توانند انگلیسی بمانند.
6. همه‌ی کنترل‌های لمسی حداقل ۴۴ پیکسل ارتفاع دارند.

## زبان و RTL

- `fa` زبان فعال محصول است و fallback رابط کاربری به فارسی انجام می‌شود.
- `dir="rtl"` در layout ریشه اعمال می‌شود.
- فونت اصلی Vazirmatn است.
- اعداد قابل مشاهده در XP، streak، درصد، شماره مرحله و رتبه با فرمت فارسی نمایش داده می‌شوند.
- آیکن‌های جهت‌دار، فلش‌ها، progress bar و مسیر مرحله‌ای باید در RTL بازبینی شوند؛ آیکن‌های مستقل از جهت مانند ستاره و قفل برعکس نمی‌شوند.
- نقش‌ها، صنعت‌ها، وضعیت‌ها، خطاها و badgeها از دیکشنری فارسی خوانده می‌شوند.

## معماری صفحات

### ۱. خانه / مسیر

- هدر فشرده با نقش فعال، streak و XP.
- یک مسیر عمودی مرکزی با نودهای گرد برای مرحله‌ها.
- نود فعال با رنگ اصلی و CTA «ادامه‌ی مسیر».
- نودهای تکمیل‌شده با وضعیت موفق و امکان مرور.
- نودهای قفل‌شده با توضیح کوتاه درباره‌ی شرط باز شدن.
- جداکننده‌ی Unit برای گروه‌بندی مرحله‌ها.
- یک کارت کوچک «هدف امروز» در بالای مسیر؛ بدون hero بزرگ یا تصویرسازی تمام‌صفحه.
- bottom navigation فارسی با مسیر، پیشرفت و پروفایل؛ خانه همان صفحه‌ی مسیر است تا تب تکراری ایجاد نشود.

### ۲. اجرای چالش

- عنوان مرحله و شمارنده‌ی تصمیم در نوار بالا.
- progress bar افقی RTL.
- سؤال در یک کارت خوانا و انتخاب‌ها در کارت‌های لمسی جدا.
- پس از ثبت انتخاب، نتیجه در همان صفحه باز می‌شود و کاربر با CTA فارسی ادامه می‌دهد.
- پایان مرحله: XP، ستاره، streak، badge جدید و مرحله‌ی بعدی بازشده.

### ۳. پیشرفت

- خلاصه‌ی XP، سطح، streak و ستاره‌ها در بالای صفحه.
- کارت‌های مهارت و صنعت با progress bar ساده.
- badgeها با وضعیت «باز شده» و «قفل».
- جدول رتبه‌بندی هفتگی به‌صورت لیست خوانا.

### ۴. پروفایل

- نقش فعال و امکان تغییر نقش.
- خلاصه‌ی تصمیم‌ها، سناریوهای تکمیل‌شده و نرخ بهترین انتخاب.
- مهارت‌ها با عنوان فارسی، شواهد و مسیر رشد.

## کامپوننت‌ها

- `PersianUserShell`: پوسته‌ی مشترک RTL، bottom navigation و safe area.
- `PathMap`: مسیر مرحله‌ای با وضعیت‌های locked/unlocked/passed و Unit separator.
- `ProgressStat`: نمایش XP، streak، سطح، ستاره و درصد.
- `LevelNode`: نود مستقل مسیر با CTA و وضعیت دسترسی.
- `ChoiceCard`: انتخاب لمسی با حالت انتخاب‌شده، خطا و غیرفعال.
- `RewardSummary`: پاداش پایان مرحله و باز شدن مرحله‌ی بعد.
- `fa.ts`: منبع واحد متن‌های قابل نمایش.

## داده و API

- از endpointهای فعلی levels، progress، badges، leaderboard، skills و sessions استفاده می‌شود.
- قرارداد API تغییر نمی‌کند مگر برای داده‌ای که هم‌اکنون برای وضعیت UI لازم است و موجود نیست.
- نام‌های داخلی انگلیسی به labelهای فارسی در لایه‌ی i18n نگاشت می‌شوند.
- در خطای احراز هویت، کاربر به ورود فارسی هدایت می‌شود؛ خطاهای شبکه در همان سطح با پیام کوتاه فارسی نشان داده می‌شوند.

## حرکت و دسترس‌پذیری

- حرکت فقط برای بازخوردهای کوتاه مانند باز شدن نود، دریافت XP و ورود کارت استفاده می‌شود.
- `prefers-reduced-motion` رعایت می‌شود.
- حالت focus، کنتراست و خوانایی روی زمینه‌های رنگی بررسی می‌شود.
- صفحه با کیبورد و لمس قابل استفاده می‌ماند، حتی اگر هدف اصلی موبایل باشد.

## محدوده‌ی پیاده‌سازی

- تغییرات فقط در تجربه‌ی مشتری و کامپوننت‌های مشترک آن انجام می‌شود.
- admin، API، Prisma و seed فعلی تغییر نمی‌کنند.
- طراحی از baseline فعلی شروع می‌شود؛ assetهای ریدیزاین قبلی استفاده نمی‌شوند.

## معیار پذیرش

- هیچ متن انگلیسی در مسیرهای customer-facing باقی نماند.
- مسیر خانه در viewportهای ۳۹۰px موبایل و ۷۶۸px تبلت بدون overflow افقی خوانا باشد.
- شروع مرحله، انتخاب گزینه، ثبت پاسخ، نمایش reveal و پایان مرحله کار کنند.
- صفحه‌ی خانه در اولین نگاه فقط یک اقدام اصلی داشته باشد.
- `tsc --noEmit` و تست دستی مسیر اصلی موفق باشند.
